# Marccent Content

Field groups, custom post types and loops for Marccent sites, with no build step. Requires [Marccent Blocks](https://github.com/marcoscenteno89/marccent-blocks) (WordPress won't activate it without): its blocks and the Marccent theme's styles and scripts come from there, one shared copy at one version, so this plugin bundles none of it.

- **Field groups**, as in ACF, built under **Fields → Field groups** (no JSON needed): a named set of fields (an office: address, phone, latitude, longitude) put on post types, on some of their posts by slug or by template, on a taxonomy's terms, on users, or on the whole site (edited under **Site content**, by anyone who edits pages). Field types: text, several lines, rich text (HTML), number, URL, email, date, yes/no, color, image, gallery, file, location (an address with its latitude and longitude, found from the address on OpenStreetMap), choice from a list, relation, and data (JSON: any names and values in one field, a form's answers or an API's item, typed as JSON and shown as a table; `{{ data }}` is all of it, `{{ data:email }}` or `{{ data:address.city }}` one value).
- **Rules on a field**: required (a post isn't published without it; drafts may be incomplete), unique (no two posts with the same SKU or email), and show only when (another field's value, as a Loop's where: `kind=office`; hidden, it isn't required). A group that repeats is a list of rows, edited beside the post as rows to add, reorder and remove; things without a page of their own (a gallery's photos, offices, the team) need no post type.
- **Post types** and their taxonomies under **Fields → Post types**, for things that need a page each; or **only in wp-admin** (no pages on the site), for what the team keeps: a form's entries (Marccent Blocks' Form, "Keep entries in": each entry a private post, everything sent in the type's Data field, `inc/entries.php`).
- Everything is kept in the database. **Fields → JSON** shows the same spec as JSON, and **Tools → Marccent export** (Marccent Blocks) exports and imports it with the site content.
- **Relations**, as Django's foreign keys and many-to-many fields: one field type, **Relation**, to the post type you pick (a contact's account), holding one post or several in an order (a work order's products). Each related post's id is a meta row of its own, so finding the posts that point to one is an indexed query, either way: a contact's `{{ account.phone }}`, an account's contacts. A related post that's deleted, a draft or password-protected doesn't show.
- **Loop block**: a query (type, count, order, also by a field, only the posts whose fields pass a where (`status=New,Scheduled&total>=1000&scheduled<today`), terms, the pages under a parent, **related** to the current post: those whose `account` is it, or its own `products`), or a repeating group's rows (from the current post, a page or the site, filtered by `service=flatwork` or `featured~home`), whose item you design once with any blocks; it repeats in the theme's grid. Loops nest: the current post of a Loop inside another is that Loop's item, so each level is related to the one around it (an account's work orders, each one's products, each product's other work orders…). An inner Loop's where can read the item around it: in a Loop of the site's Regions rows, a Loop of cities with `region={{ key }}` lists each region's cities. `{{ loop:number }}` is an item's place in its Loop (1, 2, 3…, counting on across pages): numbered steps.
- **For visitors**: a Loop can page (previous / next), offer filters (its fields, `terms:<taxonomy>`) and a search box; all of it is in the address (`?mcc1p=2&mcc1_service=curb`), so a filtered list can be shared and works without JavaScript.
- **Show if** on any block: a where on the current post's, row's or site's values (`price>0`, `phone!=`, `featured=yes`); the block renders only when it passes. A where's `*=` is "contains", and nothing after `=` / `!=` tests for empty / not empty.
- **The values in the item**: the Field block (with formats: currency, number, date, words…), `{{ tokens }}` in any block (`{{ title }}`, `{{ price | currency }}`, `{{ image:medium }}`, a button linking to `{{link}}`, a call button to `tel:{{ business.telephone }}`), or block bindings with the `marccent/field` source. In a Loop of rows, the row's fields (`{{ caption }}`, `{{ image:alt }}`); anywhere, a group's field (`{{ office.phone }}`); through relations, as far as they go (`{{ account }}`: its title, `{{ contact.account.city }}`, `{{ products.price | currency }}`: each one's). Counts and sums, as Django's aggregates, with a where after a `?`: `{{ count:work_order.account?status=New }}` (the posts pointing to this one), `{{ sum:this.products.price | currency }}` (its own), `{{ sum:this.line_items.quantity }}` (a repeating group's rows); also `average`, `minimum`, `maximum`.
- **Structured data (JSON-LD), built for every page**: the site's Organization, the WebSite, the WebPage (its type picked in a page's sidebar under **Page type**: About, Contact, Collection…; archives, author pages and searches get theirs) with its breadcrumbs, and a post's BlogPosting with its author. A post type or a field group says what it is in schema.org's words (a **Schema** box in its editor, or `"schema"` in Fields → JSON): a city is a `City` with its coordinates, the Questions rows a `FAQPage`. A post's node is on its page and wherever a Loop lists it (an ItemList); a group's rows are where a Loop shows them, so the data matches what the page shows. A value is a field's key, text with `{{ tokens }}`, or an object with its own `"@type"`; see `inc/schema.php`. Other plugins add to it (`marccent_schema_organization`, `marccent_schema_graph`; Marccent Local: the business and its places). Rank Math's Schema module stays off.
- **Global values**, anywhere (a page, the header and footer, a 404): `{{ now:year }}` (a footer's ©), `{{ now:date }}`, `{{ now:month }}`, `{{ now:day }}`, `{{ now:weekday }}`; `{{ site:name }}`, `{{ site:tagline }}`, `{{ site:url }}`, `{{ site:logo }}`; the post's author, `{{ author:name }}`, `{{ author:bio }}`, `{{ author:link }}`, `{{ author:image }}`; and on a search, `{{ search }}`. A fixed list of public values: never a setting by name, an email or a login. What a visitor typed is shown as text only, never read by a Loop's where or Show if. A cached page keeps the day it was cached.
- **Sources** (Fields → Sources): another site's API pulled into the fields when someone presses **Pull now** (or `wp marccent-content pull <source>`), never on a schedule and never live on a page. A source is an https request (keys from Appearance → Marccent settings as `{{ key:google_places }}`, filled in only as it goes out), where its items are in the answer, where they go (a repeating group's rows, the site's or a page's, or posts of a type, as drafts or published) and a map (`name = authorAttribution.displayName`, `source = "Google"`, an image copied into the Media Library with `photo:alt = …`). Items matched by fields you choose are updated, new ones added, and what you typed by hand is left alone. See `inc/sources.php`.
- **A loop inside text**: in any block's text, `{{ each:<set> }}…{{ /each }}` repeats what's between once per item, its tokens that item's: `<p>We serve {{ each:city?region=east }}{{ title }}{{ separator }}, {{ /separator }}{{ /each }}.</p>`. The set is a path as counts take (every post of a type, `page?parent=services` for the pages under one, `this.nearby`, `this.line_items`, `work_order.account`), with a where after a `?`; `| separator=", "` after the set puts that text only between items (`{{ each:city | separator=", " }}{{ title }}{{ /each }}`; for HTML between them, `{{ separator }}…{{ /separator }}` inside), `{{ else }}` starts what shows when there are none; eaches nest. Counts take a type too: `{{ count:city }}`.

```json
{
  "currency": "$",
  "types": {
    "project": {
      "label": "Projects", "singular": "Project", "slug": "projects",
      "taxonomies": { "project_service": { "label": "Services" } },
      "fields": { "city": { "type": "string" }, "price": { "type": "number" }, "before": { "type": "image" } }
    }
  },
  "groups": {
    "office": { "label": "Office", "on": [ "options" ], "fields": { "phone": {}, "latitude": { "type": "number" }, "longitude": { "type": "number" } } },
    "photos": { "label": "Photos", "repeat": true, "on": [ "page:gallery" ],
      "fields": { "image": { "type": "image" }, "caption": {}, "service": { "type": "select", "options": [ "flatwork", "curb" ] } } }
  }
}
```

Use a post type only when each item needs a page of its own (its URL, title, search meta); otherwise a group.

Works with [Marccent Blocks](https://github.com/marcoscenteno89/marccent-blocks). Requires WordPress 6.9+.

## Uninstalling

Deleting the plugin removes its settings (the content types' spec). The posts of those types, their terms, fields and
groups (the site's too, mcc_<group> options) stay: they're the site's content, and they're back as they were if the plugin is installed again with the same spec.
